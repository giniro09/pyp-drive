# PYP Drive POC — 検証ノートと設計判断

## 概要

テスラ車両のブラウザから、ブラウザGPS + OSMデータを使って次の交差点の分岐方向を抽出・提示するPOC。サーバー不要の静的サイトとしてGitHub Pagesで公開。

## アーキテクチャ

```
ブラウザ GPS (watchPosition)
    ↓
道路マッチング (ブラウザ内JS)
    ↓
交差点検出 + 分岐角度計算
    ↓
SVG交差点ダイアグラム表示
    ↓ (オプション)
Tesla Fleet API → ナビ経由地設定
```

- **地図データ**: 宇都宮駅周辺3km圏のOSM道路データを事前取得し、静的JSONとして同梱（約2.8MB）
- **処理**: グラフ構築・マッチング・交差点検出はすべてブラウザ内JavaScriptで完結
- **ランタイムAPI依存**: なし（テスラナビ連携をONにした場合のみTesla Fleet API）
- **ホスティング**: GitHub Pages（完全無料、常時HTTPS）

## 走行検証の所感（2026-09-01 宇都宮市内）

### 発見
- 「表示が先に来る → 視認で確認」という体験が新鮮。地図上では気づかない細い分岐を先に通知できるケースがあった
- ブラウザGPSの精度はPOCとしては十分。テスラCIDのChromiumブラウザで`navigator.geolocation`が動作することを確認

### 課題
- **交差点が近すぎるパターン**: 全交差点を対象にすると、連続する交差点でUIが忙しくなりすぎる。交差点を通過する前に次の交差点が表示されるケースあり
- **現実の交差点との照合**: UIが指す交差点がどの交差点なのか、ドライバーが外の景色と突き合わせにくいケースがある

## 設計判断

### 信号交差点フィルタ

上記課題への対策として、対象交差点を信号のある交差点に絞るフィルタを導入。

**根拠**:
1. 交差点同士の距離問題を自然に解決（信号交差点は一般に適度な間隔で配置されている）
2. 信号という視覚的ランドマークが、UI上の交差点と現実の交差点の照合を容易にする
3. ドライバーは信号による停車・減速タイミングで、余裕を持って方向指示できる

**3モード**:
- `すべての交差点`: フィルタなし（開発検証用）
- `信号のある交差点のみ`: 最も制約が強い
- `信号あり＋一定距離以上`: 信号交差点 + 前回対象交差点から一定距離（デフォルト150m）離れた交差点

### 道なりデフォルト選択

分岐提示時に自動で「道なり」方向を選択状態にする。

**ルール**:
- 直進（straight）がある場合 → 直進を道なりとする
- T字路（直進なし）の場合 → 左折を道なりとする（日本の交通慣習）
- いずれにも当てはまらない場合 → 最も角度差の小さい方向

ドライバーが何も操作しなければ道なり走行が継続される。変更したい場合のみタップ。

### テスラナビ連携

選択された分岐方向に沿って約500m先の道なり地点を経由地としてTesla Fleet APIに送信。

- デフォルトOFF（設定画面でON + アクセストークン入力が必要）
- CORSの制約でブラウザから直接叩けない可能性あり（要検証）
- 経由地計算は軽量な道なり探索（選択方向に最も角度差が小さい道を500mまで辿る）

## データソース

- **OSM Overpass API**: `highway=traffic_signals` タグで信号ノードを取得
- 取得範囲: 宇都宮駅(36.5592, 139.8985)を中心に半径3km
- 信号ノード数: 約946個（2026-09時点）
